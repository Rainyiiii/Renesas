## 1. 工程概述

本项目为四分类智能垃圾分拣机，采用三层装配：RA8P1 核心板插入逐飞 CPKHMI-RA8P1 扩展板，自制二级设备板再通过底面母座插入逐飞板 P4~P10。二级板承载屏幕、触摸、摄像头和全部机械接口。

完整流水线：OV5640 DVP 采集（CEU 双缓冲）→ Ethos-U55 NPU 运行 YOLO 四分类检测 → 分拣状态机驱动传送带步进电机与两个推料舵机 → ILI9488 实时显示画面、识别框与仪表盘 → FT6336 触摸控制运行/暂停/停止/数据集采集。

## 4. 机械布局与自动分拣流程（本版重点）

### 4.1 布局

```
[进料端] ──→ [j_servo2 后舵机] ──→ [摄像头] ──→ [j_servo1 前舵机] ──→
                 左格│右格                          左格│右格
```

- 传送带开机默认**正转**（把物料从进料端经摄像头送向 j_servo1 方向），DIR 低电平 = 正转。
- 摄像头位于两舵机中间；每个舵机左右各一个格子，共四格。
- **前舵机的格子**：识别后传送带**继续正转** `TRAVEL_FRONT_MS` 到位。
- **后舵机的格子**：识别后传送带**倒转** `TRAVEL_REAR_MS` 把物料送回摄像头后方。

### 4.2 360° 连续舵机控制方式

舵机为连续旋转型：脉宽只决定**转向和转速**，不决定角度。因此推料动作 = 定速旋转 `SERVO_PUSH_MS`，回位 = **显式反向旋转** `SERVO_RETURN_MS`（只发停转脉宽舵机不会自己回来），最后输出停转脉宽。

方向约定（已按实物确认）：**j_servo1 加大角度值 = 向右推；j_servo2 加大角度值 = 向左推**。

### 4.3 分拣状态机（machine_control.c）

```
WAITING（正转送料，等稳定识别：同类连续3帧 & 置信度≥0.45）
  → ALIGNING（视觉对齐：低速双向收敛，把识别框中心停到判定线±12px 内）
  → POSITIONING（停稳200ms → 前类别正转 / 后类别倒转，定时输送到舵机位置）
  → EJECTING（停带，舵机定速旋转推料 SERVO_PUSH_MS）
  → CLOSING（舵机反向旋转回位 SERVO_RETURN_MS，结束时输出停转脉宽并计数）
  → RETURNING（等待 250ms）
  → CLEARING（传送带恢复正转，画面无目标4帧后回 WAITING）
```

**视觉对齐（ALIGNING）说明**：屏幕摄像头画面里有一条**黄色虚线**＝判定线（`machine_control.h` 的 `MACHINE_ALIGN_TARGET_Y`，当前 160，数值越大线越靠画面下方、越早触发）。对齐是闭环的：物体在线下方就低速正转靠近，冲过头就低速倒转退回，落进 ±`ALIGN_TOLERANCE_PX`（12px）内才算完成——保证每次输送的起点固定。类别稳定确认后会锁定，只跟踪同类最高置信度框；回线途中连续丢框 6 帧则从当前位置进入定时输送，不再退回 WAITING 重复识别。超时 5 秒同样按当前位置继续。仪表盘状态显示 `ALIGN`。

### 4.4 类别 → 格子路由表（`g_sort_routes`，8 个数字管全部映射）

| 类别 | 默认去向 | rear | push_left |
|------|---------|------|-----------|
| 0 HARM 有害 | 前舵机左格 | 0 | 1 |
| 1 KITCHEN 厨余 | 后舵机左格 | 1 | 1 |
| 2 OTHER 其他 | 后舵机右格 | 1 | 0 |
| 3 RECOVER 可回收 | 前舵机右格 | 0 | 0 |

料斗位置和类别对不上时，直接改表里的数字即可，不需要动任何逻辑。

| 参数 | 当前值 | 状态/何时调 |
|------|--------|------------|
| `SERVO1_NEUTRAL_ANGLE` / `SERVO2_NEUTRAL_ANGLE` | 135 | 停转点。STOP 状态拨杆仍慢转就微调（一次1~3） |
| `SERVO_PUSH_SPEED` | 60 | 推料转速（1~135）。**已调好** |
| `SERVO_PUSH_MS` / `SERVO_RETURN_MS` | 1800 / 1800 | 推料/回位时长。**已调好** |
| `TRAVEL_FRONT_MS` | 15000 | 判定线→前舵机正转输送时间；8000ms 仍不足，已继续加长，待实机微调 |
| `TRAVEL_REAR_MS` | 4000 | 判定线→后舵机倒转输送时间。**已测试通过**（26 日晚） |
| `STEPPER_DEFAULT_HZ` / `STEPPER_REVERSE_HZ` | 900 / 900 | 传送带正转/倒转速度。倒转堵转（电机嗡嗡不走）才降 REVERSE_HZ |
| `TRANSPORT_SETTLE_MS` | 200 | 输送起步前停稳时间（防换向丢步） |
| `MACHINE_ALIGN_TARGET_Y`（machine_control.h） | 160 | 判定线位置（屏幕黄色虚线），越大越靠画面下方 |

| `DETECTION_MIN_SCORE` / `DETECTION_STABLE_TICKS` | 0.45 / 3 | 触发分拣的置信度与稳定帧数 |

> 挪判定线会改变输送起点：`MACHINE_ALIGN_TARGET_Y` 定了之后再标 `TRAVEL_*`，顺序别反。
> 360° 舵机回位是开环的，长期运行可能小漂移；停转点标定是根基，仍不满足就加机械挡块或换位置舵机。

## 5. 软件架构

### 5.1 工程目录（src/ 均为中文注释）

```
src/
├── hal_entry.c        # 主循环：采集→触摸→推理→分拣→显示；诊断开关都在文件顶部

├── ili9488.c/.h       # 显示驱动 + 仪表盘 + 触摸按钮绘制（RGB666 输出）
├── ov5640.c/.h        # 摄像头驱动（软件 SCCB + DVP）
├── ft6336.c/.h        # 触摸驱动（硬件 IIC1，轮询）
├── yolo_detector.c/.h # NPU 推理 + 解码/NMS/平滑 + 画框（输入 192×192）
├── machine_control.c/.h # 分拣状态机 + 舵机/步进控制（GPT 直开，见 §4）
```

### 5.2 启动流程（hal_entry 七步）

1. `ili9488_init()` 显示初始化
2. `ft6336_init()` 触摸（失败不阻塞，指示块变红）
3. `ov5640_init()` 摄像头 SCCB 配置
4. `R_CEU_Open()` 打开采集
5. `yolo_detector_open()` 打开 Ethos-U55 NPU
6. `machine_control_init()` 执行机构 GPT + 安全停止；`weight_sensor_init()`（可缺席）
7. 进入主循环（上电默认 STOPPED：画面实时预览，但不推理、不动作）

### 5.3 启动失败颜色码（纯色满屏 + 死循环）

| 颜色 | 含义 |
|------|------|
| 红 0xF800 | OV5640 SCCB 无应答（查摄像头连接） |
| 品红 0xF81F | OV5640 芯片 ID 错误，**或** CEU 打开失败（同色，按启动阶段区分） |
| 橙 0xFD20 | OV5640 寄存器写失败，**或** 执行机构 GPT 打开失败（同色） |
| 蓝 0x001F | NPU 驱动打开失败 |
| 青 0x07FF | CEU 首帧启动失败 |

### 5.4 主循环与 CEU 双缓冲

两个 153600 字节帧缓冲 ping-pong：等待 CEU 帧完成中断（`CEU_EVENT_FRAME_END` 回调置位，超时 8M 次循环）→ 启动下一帧采集 → 对完成帧做触摸轮询、推理、画框、显示。`CRAM_OVERFLOW/FIREWALL` 视为坏帧。恢复两级：软重启采集（≤8 次）→ CEU Close/Open 完全重启。SD 写卡安排在 CEU 空闲窗口，避免与采集 DMA 冲突。

### 5.5 触摸 UI

底部四个按钮（每个 80px 宽）：**▶运行 / ‖暂停 / ■停止 / 📷数据集**。暂停/停止时画面仍实时预览，仅推理和机械动作停止。进入数据集模式后四个按钮变为：**切换类别 / 拍一张 / 自动连拍开关（每帧一张，实际速度受 TF 卡写入限制）/ 退出**。触摸兼容屏幕 180° 反装。

### 5.6 仪表盘（屏幕顶部 112 行，每 4 帧刷新）

正常模式四行：`模式 分拣阶段 W重量G`｜`识别类别 置信度% X坐标 Y坐标`｜`CNT 四类分拣计数`｜`ACTIVE 当前类别 TOTAL 总数`。分拣阶段包括 `WAIT/ALIGN/POSITION/EJECT/CLOSE/RETURN/CLEAR`。数据集模式显示 SD 状态、当前类别、自动开关、四类已存数量。摄像头画面中的**黄色虚线**为视觉对齐判定线（见 §4.3）。

### 5.7 YOLO / NPU

- 输入 192×192、BGR、NCHW、int8（训练用 OpenCV 读图，注意通道序），从 RGB565 帧最近邻缩放 + 量化。
- 两个输出尺度 12×12 / 6×6，各 3 anchor；类别 HARM/KITCHEN/OTHER/RECOVER。
- 置信度阈值 0.35，NMS IoU 0.40，帧间平滑 新0.7/旧0.3；分拣触发另有 0.45/连续3帧门槛。
- 模型文件在 `src/ai_model/`（Vela 编译产物），换模型需整体替换该目录并核对输出张量名。

### 5.8 数据集采集

保存到 TF 卡 `0:/DATASET/IMG192/<类别>/`（192×192 图像）及 `RAW/`；写卡在采集间隙进行；仪表盘实时显示 SD 状态（`SD READY/NO CARD/FAT ERR/WRITE ERR` 等）与每类已存数量。

SD 卡检测通过后会等待板载电平转换/OE 稳定，并最多执行 3 次 `mediaInit()`。初始化画面的 `STEP 1031/1032/1033` 分别表示第 1/2/3 次尝试；`ERROR 3CCK` 表示命令 `CC` 的响应错误，其中 `3557` 为 CMD55 响应超时。连续三次均为 CMD55 超时时，应检查卡座接触、卡上 3.3V、PD07 卡检测以及 CMD/CLK 信号，而不是继续修改 FAT32 文件系统代码。

拍照写入时 `STEP 1101~1104` 是 BMP 创建、写入和关闭文件的进度号，不是错误码；成功后状态回到 `SD READY`，只有状态为 `SD WRITE ERR` 时底行数字才表示写入失败。

## 6. 诊断与调试开关（hal_entry.c 顶部，默认全 0）

| 开关 | 作用 |
|------|------|
| `WEIGHT_DIAGNOSTIC_ENABLE` | 只启动屏幕+称重串口，全屏显示 RX 字节数/帧数/RAW/克数。排查顺序：RX 涨=接线波特率对 → FR 涨=帧协议对 → 克数对=标定对 |
| `TOUCH_DIAGNOSTIC_ENABLE` | 触摸总线诊断画面（SDA/SCL 电平、chip ID、地址位） |
| `CAMERA_WIRING_TEST_ENABLE` | OV5640 输出测试图，逐根检查 DVP 数据线（8 色条报告） |
| `CAMERA_HOLD_TEST_PATTERN` | 保持测试图不退出 |
| `TOUCH_UI_ENABLE` | 置 0 可完全关闭触摸功能 |

## 7. FSP 配置要点

### 7.1 栈大小（CRITICAL）

- `ra_cfg/fsp_cfg/bsp/bsp_cfg.h`：`BSP_CFG_STACK_MAIN_BYTES = 0x4000`（16KB），堆 0x1000。
- **每次 FSP Generate 都会把栈重置回 0x400！必须改回，且改后删除 Debug 文件夹重新编译**（否则 startup.o 不重编，不生效）。

### 7.2 外设配置一览

| 实例 | 用途 | 关键参数 |
|------|------|---------|
| g_spi1 | 显示屏 | SPI Mode 0，MSB，15.625MHz，回调 `spi_callback`，无 DMA |
| g_ceu_qvga | 摄像头 | 320×240×2B，DATA_SYNCHRONOUS，8-bit，HSYNC/VSYNC 高有效，8/16-bit 均字节交换，回调 `g_ceu_callback` |
| g_weight_uart | 称重 | SCI4，9600 8N1，回调 `weight_uart_callback` |
| g_i2c_master0 | 触摸 | IIC1，FT6336 |
| g_rm_ethosu0 | NPU | Ethos-U55 |
| SDHI0 + DMAC | TF 卡 | FatFS |
| GPT0 | 背光 PWM 接口 | 代码里改为 GPIO 控制 |

### 7.3 GPT 与 machine_control 的关系（重要）

GPT5（双通道舵机）、GPT7、GPT12（步进）、GPT13（备用舵机）由 `machine_control.c` **直接用 FSP GPT API 打开**，不在 Stacks 页面添加实例。做 Generate 后重点确认 **P501 仍为 GPT12 GTIOCA**、P915/P914/P807/P304 复用未被还原成普通 GPIO。

## 9. 已知问题与注意事项

1. **FSP Generate 副作用**：栈重置（§7.1）；`Debug/src/subdir.mk` 在 clean 后自动重建，可能重新引入已删除的源文件（如 st7789 残留）；pin_data.c 可能丢配置（尤其 P501）。
2. **GPIO 操作**：PCNTR3 原子寄存器在 RA8P1 上不可靠，全部用 PODR 读改写；写 PFS 前后必须解锁/锁定 PWPR。
3. **ILI9488 init 序列与面板强相关**：必须用 CL40BC299-40A 厂商 4SPI Demo 序列，其他参考代码 = 无显示。颜色偏色调 MADCTL bit3（BGR）或字节序。
4. **360° 舵机为开环控制**：回位精度依赖停转点标定和推/回时长对称性，见 §4.5 注意事项。
5. **启动颜色码有重复**（品红、橙各对应两种故障），按启动到哪一步区分。
6. **动力电源**：舵机/步进用外部 5V/8.4V/12V，与 RA8P1 共地，绝不可接入 RA8P1 3.3V；舵机动作导致系统重启 = 查外部电源容量与共地。
7. **（已修复，留档）状态计时器 32 位溢出**：旧版 `state_elapsed()` 用"毫秒×每毫秒周期数"直接比较 CYCCNT，时长超过约 4 秒即溢出回绕，症状是"时间参数改大了实际时长不变"。2026-07-26 已改为毫秒累加器实现，任意时长真实生效。若未来新增长时限逻辑，直接用 `state_elapsed()` 即可，不要自己拿 CYCCNT 乘毫秒。
